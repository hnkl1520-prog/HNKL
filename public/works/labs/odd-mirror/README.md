# Odd Mirror — 조합형 캐리커처

## 열기

- `odd-mirror.html`: 카메라 앱. HTTP 실행은 함께 저장한 vendor/ 도구와 모델을 사용합니다. 카메라 권한이 필요하며 얼굴 인식 및 분할은 기기 안에서 처리합니다. 파일 직접 열기는 CDN을 사용하므로 인터넷이 필요합니다.
- `index.html`, 기존 `parts.html` 주소: 카메라 시작 화면으로 바로 이동합니다. 사용자 진입에서 조합 페이지를 제거했습니다.
- `style-study/index.html`: 이전 정적 조형 시안과 사용자 제공 레퍼런스.
- 로컬 미리보기: 저장소 루트에서 `node test/odd-mirror/preview.mjs`, 이후 `http://127.0.0.1:8012/works/labs/odd-mirror/odd-mirror.html`.

## 컴포넌트 구조

그리기 원본은 `src/components.js`, 스캔 완료 판정과 옷 측정은 `src/appearance.js`, 얼굴 추론 워커는 `src/tracking.js`입니다. 세 파일 모두 통합 HTML에 내장됩니다. 수정 후 저장소 루트에서 `node test/odd-mirror/build-components.mjs`를 실행해 통합본을 갱신하세요. 개발용 조합 도구는 `test/odd-mirror/component-studio.html`에 보관하며 카메라와 같은 부품 코드를 씁니다. `src/parts.js`는 이 검토 도구에만 사용됩니다.

| 부위 | 부품 |
|---|---|
| 얼굴형 | 긴 U형, 좁아지는 턱, 넓고 각진 턱, 둥근 볼, 달걀형, 아래로 넓어지는 볼 |
| 눈 | 둥근 사각 눈, 가로로 둥근 눈, 무거운 눈꺼풀, 둥근 눈, 작은 캡슐 눈, 비스듬한 둥근 눈 |
| 눈썹 | 가는 곡선, 두꺼운 곡선, 각진 눈썹 |
| 코 | 긴 물방울 코, 둥근 쐐기 코, 작고 둥근 코, 넓은 코 — 얼굴색보다 한 톤 짙은 면 |
| 입 | 평평한 입, 부드러운 입, 도톰한 입술, 윗입술이 도드라진 입 |
| 헤어 | 없음, 두상에 붙은 머리, 둥근 앞머리, 옆으로 흐르는 머리, 뒤로 넘긴 머리, 단발, 긴 머리 |
| 안경 | 없음, 둥근 테, 각진 테 |

완성 캐릭터 유형을 선택하지 않습니다. `fromMeasurements()`가 **각 부위를 독립적으로 선택**하고 그 사람의 측정값으로 폭·길이·간격·기울기를 변형합니다. 개발용 조합 도구에서는 같은 얼굴형에 다른 눈·코·헤어를 적용하고, 반대로 나머지 부품을 고정해 얼굴형 6개를 비교할 수 있습니다.

종류 선택 기준은 미술적 규칙입니다. 얼굴 길이/폭, 턱 폭/얼굴 폭, 눈 개방 비율, 눈썹 두께, 코 길이, 입꼬리·입술 비율을 활용합니다. 이 경계는 통계적으로 검증된 인물 분류가 아닙니다. 부품 선택은 스캔에서 한 번 결정해 경계 근처에서 부품이 깜빡이지 않습니다. 최종 비례는 기존의 신뢰도 보정·과장 결과를 사용합니다.

헤어는 정렬된 분할 마스크의 길이·부피·헤어라인을 몇 가지 큰 덩어리로 단순화합니다. 높은 헤어라인과 볼륨이 관측되면 이마가 드러나는 넘긴 머리 부품을 씁니다. 실제 모발 방향을 측정하는 기능은 아니므로 스타일 정확도는 별도 검증이 필요합니다. 곱슬·묶은 머리 같은 세부 스타일은 아직 별도 부품이 없습니다. 안경은 기존 실험적 추정이 확인한 경우에만 적용하며 렌즈 크기를 조정합니다. 미관측 헤어와 미확정 안경은 임의로 추가하지 않습니다.

## 라이브 동작

1. 정면에 가까운 표본을 모아 형태와 부품 조합을 결정합니다.
2. 얼굴 표본 8개, 헤어 결과 2개, 옷 결과 2개와 안정된 옷 색을 모읍니다. 4.5초부터 미확정 안경은 보류한 채 진행할 수 있습니다. 얼굴을 찾은 뒤 8초가 지나고 얼굴 표본이 8개 이상이면 부분 결과로 전환하며 미확인 외형을 표시합니다. 얼굴 표본 자체가 부족하면 자동 완료하지 않습니다. 4초 이후 표본 3개 이상이면 직접 진행할 수도 있습니다. 초기 모델 준비 시간은 이 제한에 포함되지 않습니다.
3. 표정·시선·고개는 움직입니다. 얼굴형과 부품 종류, 헤어·안경은 고정됩니다.
4. 수동 ‘다시 스캔’은 색을 유지하면서 외형을 다시 읽습니다. 새 사람이 들어오는 자동 스캔은 유지합니다.
5. ‘모습 보정’에서 헤어·안경·옷 색을 조정할 수 있습니다. 직접 보정은 관측과 구분하고 같은 사람의 재스캔에 유지합니다. 헤어·안경의 ‘자동’과 ‘옷 색 자동으로’는 스캔 결과를 복원합니다. 새 사람은 자동으로 시작합니다.
6. ‘원본 보기’는 작은 카메라 화면을 켭니다. ‘마치기’와 스캔 중 ‘돌아가기’는 카메라 스트림·모델을 해제하고 시작으로 돌아갑니다. 취소 후 뒤늦게 승인된 스트림도 즉시 해제합니다.

D 키로 부품 선택, 신뢰도, 관측/추정 정보를 확인할 수 있습니다. 그래픽은 평면 채색, 제한된 제어점, 면으로 된 코를 사용합니다. 코는 피부 팔레트에서 파생한 색, 입술과 입 안은 얼굴색에 맞춘 낮은 채도의 자주색입니다. 벌림 높이와 입술 면을 줄이고 혀처럼 보이던 아래 타원 면을 제거했습니다.

동공은 C안의 짧은 타원형을 쓰며, 눈 종류에 따라 비율을 조금 조정합니다. 눈을 크게 떠도 동공의 크기·중심이 늘어나지 않습니다.

옷은 기존 분할 모델의 clothes 채널과 별도 상체 크롭에서 대표 RGB 색을 읽습니다. 여러 표본의 중앙값으로 작은 프린트·조명 반짝임을 줄입니다. 어깨가 화면 안에 보이면 폭, 목선이 관측되면 깊이를 반영합니다. 잘린 어깨 폭은 추정으로 남깁니다. 옷의 세부 종류·재질·로고·정확한 칼라 형태는 읽지 않습니다. 옷을 보지 못하면 중성색을 쓰고 미확인으로 표시하며, 검정 옷으로 확정하지 않습니다.

시작·로딩 화면은 밝은 중성 배경을 사용합니다. 스캔 중에는 카메라 미리보기와 실제 표본 수에 따른 준비 상태를 보여 줍니다. 헤어는 얼굴형의 관자놀이 폭에 맞춰 연결합니다. 앞머리 높이를 정리하고 눈썹이 머리카락 위에 붙어 보이지 않도록 레이어를 조정했습니다.

입 중앙과 입꼬리 움직임을 분리해 찡그림이 미소로 남던 렌더링 문제를 수정했습니다. 찡그림 점수와 입술 누르기가 실시간 평활화와 렌더링까지 이어집니다. 스캔 때의 기본 표정 점수를 빼서 평소의 웃음·찡그림 오프셋이 반복 적용되지 않게 합니다. 대기 중에는 최근 표본으로 갱신하므로 처음 받은 나쁜 표본에 고정되지 않습니다. 눈은 기본 부품을 유지하면서 반감김·크게 뜨기·윙크·아랫눈꺼풀 상승·시선을 표현합니다. 무표정에 일괄 웃음 곡률을 추가하지 않습니다. 이는 렌더링과 입력 연결의 수정이며 실제 얼굴의 표정 인식 정확도를 검증했다는 뜻은 아닙니다.

안경은 눈 주변 크롭을 확대하고 낮은 렌즈의 아랫테도 탐색합니다. 분할의 ‘기타’ 클래스는 안경 전용이 아니므로 검출 점수에서 제외했습니다. 테 크기와 모서리를 함께 맞추고 약한 윗테는 추정으로 표시합니다. 실제 영상 검증 전까지 실험적 기능이며, 충분한 형태 근거가 없으면 임의 테를 자동 적용하지 않습니다.

가상 카메라 검증은 CPU 진단 모드로 실행했습니다. 처음의 작은 얼굴 입력은 검출되지 않아 얼굴을 확대한 입력으로 흐름을 확인했습니다. 이는 반복 사진을 이용한 통합 동작 검증이며, 실제 사람의 움직임이나 GPU 성능 검증은 아닙니다. 생성된 비교 시트와 화면 캡처는 저장소의 `test/odd-mirror/results/`에 있습니다.

실제 카메라에서 다양한 인물·조명·가림·안경/헤어 종류에 대한 정확도와 체감 속도는 별도 확인이 필요합니다. 부품 연결 완료와 개인을 닮는 정도의 검증은 구분합니다.

2026-09-20 v4 HTTP 가상 카메라 재검증에서는 시작·스캔 완료·외형 고정·안경 보정·재스캔 색 유지·콘솔 오류 없음까지 확인했습니다. 초기 스캔의 헤어 표본은 0개였고, 추정 비율이 76%인 대체 얼굴로 완료되었습니다. 분할 모델이 준비되었다는 사실과 헤어를 실제로 읽었다는 사실은 다릅니다. 이번 결과로 헤어·안경 정확도나 인물 유사도를 통과 처리하지 않습니다.

이 결과는 실제 관객의 표정·안경·헤어 정확도나 전시장 처리 속도를 보증하지 않습니다. 안경 형태 추정은 실험적이며 헤어는 거친 실루엣 분류입니다. 웹에 방명록/공동 초상 저장 기능은 아직 추가하지 않았습니다.

## v6 수정 — 2026-09-21

- 수평 입 당김을 웃음에 더하던 항을 제거했습니다. 웃음 점수가 높아도 입꼬리 상승이 없으면 미소를 만들지 않습니다. 코 찡그림·윗입술 올림·입술 압착을 분리하고 비대칭 윗입술을 그립니다. 해당 동작은 초기 무표정 표본에서도 제외합니다.
- 허용 각도 안의 작은 고개 오차가 얼굴 전체의 개인차를 지우던 신뢰도 감점을 수정했습니다. 입 표정 때문에 눈·눈썹까지 일괄 감점하지 않습니다. 이는 내부 보정 규칙 수정이며 정확도 상승률이 아닙니다.
- 헤어 경계를 못 읽었다고 눈까지 덮는 앞머리를 채우지 않습니다. 이마 노출을 얼굴 높이에 상대적으로 판단하고, 넘긴 머리·옆으로 흐르는 머리의 외곽과 이마선을 구분했습니다. 모발 방향을 측정하는 별도 모델은 여전히 없습니다.
- 얼굴 분석과 안경 경계/렌즈 맞춤을 별도 워커에서 실행합니다. 얼굴 입력은 최대 640px, 한 번에 한 프레임만 처리합니다. 렌더링은 분석 결과 사이에서도 표정을 보간합니다. 분할 실패 시 UI 스레드로 무거운 분석을 옮기지 않고 미확인 상태로 남깁니다.
- HTTP는 `vendor/`에 저장한 기존 MediaPipe 1.0.1과 같은 모델을 사용합니다. 새로운 모델을 추가한 것이 아니며 CDN 대기와 워커 초기화 시간 초과를 줄이기 위한 변경입니다. HTML과 vendor 폴더를 함께 제공해야 합니다. 파일 직접 열기는 CDN 대기와 브라우저 제한이 있으므로 로컬 서버 실행을 권장합니다.

검증: `expression-components.test.mjs`에서 가로 당김·충돌하는 높은 웃음 점수·Eww·윗입술 비대칭을 검사했습니다. `components-browser.mjs`에서 576가지 헤어 연결과 입의 낮은 채도를 검사했고, 13표정 시트를 눈으로 확인했습니다. 실제 모델/반복 사진/CPU/로컬 HTTP 검사 2회에서 준비 1.0~1.5초, 전체 4.7~5.2초, 화면 간격 p95 16.7ms, 얼굴 추적 약 20회/초를 기록했습니다. 최근 결과는 `test/odd-mirror/results/v6-flow-http.json`입니다. 헤어 2개·옷 2개 표본으로 자동 완료했고 재스캔·보정·종료도 통과했습니다. 실제 카메라의 표정 대응·닮음·넘긴 머리 인식과 전시장 성능을 검증한 것은 아닙니다.

중간 검사에서는 CDN 대기 후 메인 스레드 대체 실행이 40초 이상 준비 지연과 화면 지연을 만들었습니다. 로컬 HTTP 경로와 분할 대체 실행 중단은 그 뒤 추가한 개선입니다. 파일 직접 열기에 같은 속도를 보장하지 않습니다.

일반 실행과 같은 GPU 우선 경로도 로컬 HTTP에서 확인했습니다. 실제 선택된 delegate는 GPU, 준비 1.0초, 전체 5.2초, 화면 간격 p95 16.7ms였습니다 (`test/odd-mirror/results/v6-flow-http-gpu.json`). 이 수치는 같은 사진을 반복하는 헤드리스 테스트 환경의 결과이며 실제 카메라에서의 보장값이 아닙니다.

추론의 동기 실행과 워커 분리는 [MediaPipe 공식 웹 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js)를 참고했습니다.
