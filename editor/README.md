# HNKL 에디터

포트폴리오 페이지의 간격·크기 같은 세부 값을 화면에서 보면서 고치고, 그대로 코드에 저장하는 도구.

## 실행

```bash
cd editor
npm install     # 처음 한 번만
npm start
```

http://localhost:5180 열기.

## 쓰는 법

1. 위쪽에서 편집할 페이지 고르기
2. **요소 고르기** 누르고, 미리보기에서 고칠 부분 클릭
3. 오른쪽에서 값 조정 (입력칸에서 위/아래 화살표키로도 조절, Shift 누르면 10씩)
4. **파일에 저장**

저장 전까지는 미리보기에만 반영되고 파일은 그대로다. **되돌리기**를 누르면 원래대로 돌아간다.

## 적용 범위 두 가지

| 방식 | 하는 일 | 언제 |
|---|---|---|
| **같은 규칙 전체** | CSS 규칙을 직접 고침 | 기본. 같은 클래스 쓰는 곳이 함께 바뀜 |
| **이 요소만** | 그 태그에 `style="…"` 을 붙임 | 하나만 예외로 두고 싶을 때 |

'같은 규칙 전체'에서 각 속성 아래에 **어느 규칙이 그 값을 정하는지** 표시된다.
`.aff-kw-card 에 추가` 라고 나오면, 그 규칙에 없던 속성이라 새로 넣는다는 뜻이다.
(`padding` 처럼 한 줄로 묶여 있고 안에 `var()` 가 있으면 브라우저가 `padding-top` 을
따로 알려주지 못해서, 이렇게 규칙에 직접 추가한다.)

## 화면 크기 버튼

미리보기를 실제 그 크기로 렌더링한다. `vw` 단위와 `@media` 가 진짜로 반응하므로,
노트북에서만 깨지는 문제 같은 걸 바로 확인할 수 있다.

- 데스크탑 2560 / 노트북 1536 / 태블릿 1024 / 폰 390

옆의 **보기** 슬라이더는 화면에 표시되는 배율만 줄인다. 값에는 영향이 없다.

## 배포 안전

에디터는 `public/` **밖**에 있고, 편집용 스크립트는 로컬 서버가 페이지를 보낼 때만
끼워 넣는다. 원본 HTML에는 흔적이 남지 않으므로 배포 전에 지울 것이 없다.
`firebase deploy` 는 `public/` 만 올린다.

## 검증

```bash
node lib/patch.test.js       # 단위 테스트
node lib/realfile.test.js    # 실제 페이지 복사본으로 검증 (원본은 안 건드림)
```

`realfile.test.js` 는 대상 파일을 임시 폴더로 복사한 뒤 그 복사본만 수정한다.
다른 페이지를 시험하려면 경로를 넘기면 된다:

```bash
node lib/realfile.test.js ../public/works/projects/capus/capus.html
```

## 구조

```
server.js          로컬 서버 — 에디터 화면 + public/ 서빙(스크립트 주입) + 저장 API
app/               에디터 화면 (좌: 미리보기 / 우: 속성판)
inject/bridge.js   미리보기 안에서 도는 스크립트 — 요소 고르기, 값 알려주기, 즉시 반영
lib/patch.js       원본 파일을 '건드린 줄만' 고치는 로직
```

`lib/patch.js` 는 parse5로 위치만 알아낸 뒤 원본 문자열의 그 구간만 잘라 끼운다.
파일을 통째로 다시 써내지 않으므로 들여쓰기·주석이 유지되고, git diff에도 고친 줄만 뜬다.
